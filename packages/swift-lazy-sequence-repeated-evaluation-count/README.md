# Swift lazy 시퀀스의 클로저 재평가 횟수 측정

Swift `lazy` 시퀀스와 컬렉션에서 변환 클로저가 언제, 몇 번 호출되는지를 측정한다. eager `map`과 비교하여 lazy 평가의 특성과 함정을 확인한다.

## 질문

1. eager `map`은 생성 시점에 원소 수만큼 클로저를 호출하는가?
2. `lazy.map`은 생성만으로는 클로저를 호출하지 않는가?
3. `lazy.filter{...}.map{...}.first` 같은 체인은 첫 일치 원소까지만 평가해 단락되는가?
4. 같은 lazy 시퀀스를 두 번 순회하면 클로저가 다시 호출되는가? (결과 캐시 없음)
5. lazy map 결과에 인덱스로 여러 번 접근하면 접근마다 재평가되는가?
6. 반복 사용할 결과는 `Array(...)`로 한 번 물질화하면 이후 접근은 추가 호출이 없는가?

## 헷갈리는 점

### 1. Lazy 시퀀스의 재평가

lazy 시퀀스를 두 번 순회하면 클로저가 매번 다시 호출된다. 결과를 캐시하지 않기 때문이다. 이는 부수효과가 있는 클로저를 lazy에 넣으면 예상치 못한 동작이 발생할 수 있음을 의미한다.

```swift
var count = 0
let lazy = [1, 2, 3].lazy.map { value -> Int in
    count += 1
    return value * 2
}

// 두 번 순회하면 count가 6이 된다
Array(lazy)  // count = 3
Array(lazy)  // count = 6
```

### 2. 인덱스 접근의 재평가

lazy 컬렉션의 인덱스 접근은 매번 해당 원소를 재계산한다. 같은 인덱스에 여러 번 접근하면 그만큼 클로저가 호출된다.

```swift
let lazy = [1, 2, 3, 4, 5].lazy.map { $0 * 2 }
let _ = lazy[2]  // 1회 호출
let _ = lazy[2]  // 또 1회 호출
let _ = lazy[2]  // 또 1회 호출
// 총 3회 호출됨
```

### 3. 해결책: 물질화

반복적으로 사용할 lazy 결과는 `Array(...)`로 한 번 물질화하면 이후 접근은 추가 계산 없이 저장된 값을 반환한다.

```swift
let lazy = [1, 2, 3, 4, 5].lazy.map { $0 * 2 }
let materialized = Array(lazy)  // 5회 호출, 결과 저장
let _ = materialized[2]  // 0회 호출
let _ = materialized[2]  // 0회 호출
```

### 4. 부수효과와 lazy

부수효과(카운터, 출력, 네트워크 요청 등)가 있는 클로저를 lazy에 넣으면 위험하다. 예상치 못한 시점에, 예상치 못한 횟수만큼 실행될 수 있다. lazy는 순수 함수로만 사용하는 것이 안전하다.
